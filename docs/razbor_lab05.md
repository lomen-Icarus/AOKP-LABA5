- Направленный свет и фоновый свет из `main.rs` заменены ресурсом `SceneLight` (`src/light.rs`) с точечным источником в (8, 10, 6).

## Модель Фонга в двух словах

Цвет точки = диффузная часть + блик + фоновая часть + самосвечение.

- Диффузная зависит от угла между светом и поверхностью и не зависит от того, откуда смотрим. Поэтому при вращении камеры освещённая сторона тора остаётся на месте.
- Блик зависит от положения наблюдателя. Поэтому при вращении камеры блик ползёт по тору.
- Чем больше `shininess` (p), тем меньше и резче блик.

## Перевод в Bevy

Bevy считает освещение физически (PBR), там нет «p» и «Ms», есть шероховатость и `reflectance`.

| Фонг | Bevy |
|---|---|
| diffuse | `base_color` |
| specular | `reflectance` = наибольшая компонента specular |
| shininess p | `perceptual_roughness` = √√(2 / (p + 2)), не меньше 0,089 |
| emission | `emissive` |

p = 0, 16, 64, 128 даёт шероховатость 1,00; 0,58; 0,42; 0,35.

## Как работает `load`

1. `fs::read_to_string` читает файл; при ошибке `?` сразу возвращает `Err` с именем файла.
2. Каждая строка делится на слова: первое — имя параметра, остальные превращаются в числа.
3. `match (key, values.as_slice())` проверяет и имя, и количество чисел: `diffuse` ждёт ровно четыре, `shininess` — одно.
4. Любая другая строка — ошибка с номером строки.
5. В `setup_scene` ошибка не роняет программу: `unwrap_or_else` печатает сообщение и подставляет материал по умолчанию (серый матовый).

## Агрегация и Handle

- Позиция и угол принадлежат объекту — композиция.
- Материал и меш лежат в хранилищах `Assets<...>`, объект хранит только ссылку `Handle` — агрегация.
- `Handle` работает как `shared_ptr` в C++ или `Rc` в Rust: `clone()` копирует ссылку, а не материал. Материал удаляется, когда исчезает последняя ссылка.
- Чтобы два тора делили один материал, достаточно дать им одинаковый `material_index` в `data.rs`.

## Вопросы для защиты

| Вопрос | Ответ |
|---|---|
| Почему блик двигается, а освещённая сторона нет? | Блик зависит от наблюдателя, диффузная часть — нет. |
| Чем матовый материал отличается от глянцевого в файле? | `specular` 0 и `shininess` 0 у матового; `specular` 1 и большой `shininess` у глянцевого. |
| Зачем материалы в файлах? | Чтобы менять цвета без перекомпиляции. |
| Что будет при ошибке в файле? | Сообщение в консоль и материал по умолчанию; программа продолжает работу. |
| Почему материал хранится как `Handle`, а не копией? | Материал может быть общим для нескольких объектов — агрегация. |
| Что делает `clone()` у `Handle`? | Создаёт ещё одну ссылку; сам материал не копируется. |
| Когда материал удаляется из памяти? | Когда удалена последняя сильная ссылка на него. |
| Зачем `is_changed()` в `apply_light`? | Не переписывать источник каждый кадр, если параметры не менялись. |
| Почему запускать из папки проекта? | Пути к файлам материалов относительные. |
| Что такое `range` у `PointLight`? | Радиус действия: дальше него источник не освещает. Взят с запасом, 50. |
